# lineage-first-credit-bench

Open reference implementation and benchmark of lineage-first ingestion for multi-tenant credit data. Two ingestion designs run against the same synthetic workload: a baseline in which each integration keeps its own audit log, and a lineage-first design with one independent, append-only lineage substrate. The benchmark measures integration cost, audit replay, tenant isolation, and alternative-data fault escape.

All data is synthetic and generated by seeded code in this repository ([DATA_SPEC.md](DATA_SPEC.md)). The benchmark tests mechanisms in a controlled setting; it makes no claim about any production platform.

## Research questions

| | Question | Experiment |
|---|---|---|
| RQ1 | How does the change footprint of adding the Nth data source differ with and without a lineage substrate? | `experiments/rq1_footprint.ts` over tags `rq1-s0` to `rq1-s8` |
| RQ2 | How quickly and how completely can each design reconstruct the exact inputs to a past decision? | `experiments/rq2_replay.ts` |
| RQ3 | What do silo, pool, and bridge tenancy cost, and do isolation tests pass under each? | `experiments/rq3_tenancy.ts` |
| RQ4 | How many injected alternative-data faults reach decisions with and without an ingestion quality layer? | `experiments/rq4_faults.ts` |

## Layout

| Path | Contents |
|---|---|
| `src/generator`, `src/providers` | Seeded synthetic world and eight fictional providers (the outside world) |
| `src/adapters` | Source adapters shared by both designs |
| `src/lineage` | Lineage-first design |
| `src/baseline` | Baseline design and per-integration audit logs ([docs/BASELINE_DESIGN.md](docs/BASELINE_DESIGN.md)) |
| `src/quality` | Ingestion quality layer ([docs/QUALITY_LAYER.md](docs/QUALITY_LAYER.md)) |
| `src/decision` | Toy rule-based decision model (a harness, not a contribution) |
| `src/tenancy`, `src/access`, `src/api` | Tenancy modes, isolation suite, attribute-based access policy, API layer |
| `results/raw` | Raw experiment output; `results/derived/numbers.json` holds every reported number |
| `analysis` | `verify_numbers.py` (every number and consistency check) and `plot_figures.py` |

## Run

```bash
docker compose up -d db
npm ci
npm test
```

Reproduce every result, number, and figure (two to three hours on a 10 core laptop):

```bash
npm run reproduce
```

Hardware, runtimes, and the commit behind the committed results are in [ENVIRONMENT.md](ENVIRONMENT.md).
